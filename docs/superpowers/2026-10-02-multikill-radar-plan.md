# 多杀选片与可选雷达实施计划

依据：已批准的 `specs/2026-10-02-multikill-radar-design.md`。执行方式建议：当前会话按下列阶段顺序实施，不使用子代理。每阶段测试失败先修复，不删除、跳过或降低验收要求。

## 1. 核实解析字段

读取 `adapters/demo.py`、`tests/integration/test_real_demo.py` 和现有缓存校验测试。通过独立脚本只读解析原始 Demo 的 player_death 事件，核对攻击者、受害者、队伍、热身和 tick 的实际类型与含义；仅输出必要字段和少量样例，不复制 Demo。字段缺失不得用昵称或当前队伍猜测事件发生时的身份。

在 `docs/validation/stage-5-multikill.md` 保存字段及样本核对结果。新增解析适配测试，包括缺失字段、无效身份、同 tick 不同受害者；保留原有死亡事件安全判断。真实解析失败时先修复或明确字段支持问题，不实现建立在猜测字段上的候选算法。

验证：`./scripts/test.ps1 -TestPaths tests/unit/test_clips.py,tests/integration/test_real_demo.py`。必要时分别调用两个测试文件，避免 shell 数组传参差异。原始文件解析需要权限时给出可见提示。

## 2. 候选服务及缓存升级

新增 `src/cs2pov/services/highlights.py` 和 `tests/unit/test_highlights.py`。

- 分析数据增加有效击杀和分析缺项说明；schema 升级为 2，缓存前缀同步升级。修改 `demo_worker.py` 的结构及版本检查，旧缓存不作为新结果使用。
- 候选身份包含玩家稳定 ID 和回合 ID；携带全部击杀 tick、可录边界、默认范围、截短原因及不可用原因。
- 先过滤热身、自杀、队友击杀、未知身份/队伍，再去重；每个完整回合至少两杀生成一个候选，不按时间间隔拆分。
- 计算包含全部击杀的连续存活范围，并与回合及 Demo 边界相交；死亡事件单独限制右边界。默认前后各 10 秒，取有效 tick。
- 暴露统一范围校验入口，UI 和草稿保存均调用；空区间、越界、缺失击杀、跨死亡一律拒绝。

测试：2/3/5 杀、远距离间隔、跨回合、同名不同 ID、重复事件、同 tick 多杀、缺字段、热身、自杀、队友击杀、首尾边界、死亡同 tick、存活中断、不完整回合、非整数时间比例；旧缓存重算、损坏缓存重算、旧草稿保留。不能修改既有整回合/自定义选择的安全标准。

通过条件：新增业务测试及原 `test_clips.py`、缓存相关测试全部通过；报告 A20 的自动检查结果。

## 3. 草稿和选择流程

修改 `services/workspace.py`、`services/clips.py` 中选择分派，以及 `tests/ui/test_demo_workflow.py`。

新增多杀选择方式；保存时由当前分析重新生成并定位候选，再验证范围，不能信任 UI 传入的 kill tick。快照保留候选、实际范围、全部击杀、截短原因、Demo 内容 hash 和原 HUD 参数。

兼容旧 round/time 草稿；新草稿重新打开后显示选择摘要，只有当前文件分析内容一致时才恢复可编辑候选。切换玩家、Demo 或取消解析后清除旧选中态。损坏或失效草稿说明问题，不自动准备游戏。

测试：修改候选 ID、缺少击杀、越界范围、源文件变化、旧草稿加载、切换玩家同名、保存后重开。验证保存时二次校验确实拒绝错误输入。

## 4. 可拖动时间轴

新增 `src/cs2pov/ui/clip_timeline.py` 独立 Qt 组件及 `tests/ui/test_clip_timeline.py`。在 `ui/window.py` 的 Demo 与片段页接入候选列表、状态说明、时间轴和精确时间输入。

时间轴显示整个可调范围、全部击杀标记和双柄选区；左右柄只能调整击杀核心外的余量。允许 Tab 选择手柄、方向键按有效 tick 调整，并同步起止时间、时长和前后余量。鼠标超出控件、窗口缩放及同 tick 标记重叠不能产生非法范围。

无候选、数据不完整和不可用候选分别说明；禁用无效保存操作。保留现有整回合和自定义入口，不加入画面缩略图。首页读取已保存草稿摘要，不另建状态。

测试真实鼠标拖动与键盘事件：两端极限、跨柄尝试、精确输入同步、同 tick 核心、短范围、缩放、切换玩家/文件、不可用候选、草稿恢复。运行全部 UI 测试，检查旧流程无回归。

## 5. 多杀集成验收

在原始 Mirage Demo 上选择实际多杀候选，逐项核对玩家、回合、全部击杀 tick 和默认范围。记录解析核对与游戏目视核对的区别。若需游戏目视验证，先给用户明确操作提示，沿用备份、-insecure 及恢复流程，不录制也不复制资源安装。

运行 `./scripts/test.ps1` 完整回归和 pip check，记录准确数量、失败及未验证项，更新 A20–A22。已有阶段 6 回读问题仍保持未完成，不因多杀模块通过而启用不可靠准备流程。

## 6. 雷达专项验证

先检查 `local-validation/radar-probe/RESULTS.md` 和资源来源/许可材料。核实按队伍隐藏 CSS 是否使全部敌方不可见；无法表达被发现状态时报告功能不符合要求，不能通过改验收标准解决。

建立两地图 × CT/T 验证表，覆盖队友移动、未暴露敌人、已暴露敌人、失去视野、死亡切人以及显示/隐藏。当前仅有 Mirage 样本；第二地图 Demo 或需要用户配合的画面核对，届时只问一个具体问题并给出操作提示。不要另行下载未知大文件或复制游戏。

资源授权、内容审查、信息正确性、游戏版本和资源 hash 兼容性全部通过后，才升级正式资源白名单。每次实机退出独立校验恢复 hash、临时文件清除及进程退出，保留证据。A23 未通过时不能宣称整版完成。

## 7. 雷达开关集成与最终回归

通过阶段 6 后，在 `storage/settings.py` 的 HUD 预设及任务快照增加布尔 `show_radar`；旧数据迁移为 false，保留原值和备份。HUD 页提供显示开关，兼容状态未通过时禁用并说明原因；业务层也拒绝未验证 true。

修改 `resources/pov_visibility.js` 与 `services/replay.py`，使用经验证的资源及显示/隐藏命令；不能一边脚本强制隐藏一边声称开关有效。游戏/资源版本变化使显示资格失效。

测试默认隐藏、旧预设/草稿迁移、任务快照隔离、伪造 true、兼容失效、显示/隐藏命令、恢复及既有 HUD 行为。实机检查画面和成片，随后再次运行 `./scripts/test.ps1` 全量测试并更新验收矩阵、PRD 和进度。
